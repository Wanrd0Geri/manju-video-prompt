# Manju 发布时语义评测规程

本规程只用于发布门禁，不进入日常提示词编译上下文。评测对象是候选 Skill 对 `manifest.json` 各案例的实际回复。这里不设置逐字 gold 提示词；评审只依据来源事实、结构化 oracle 和成片可执行性判断。

## 1. 评测顺序

1. 对每个 case 独立运行候选 Skill，并保存完整回复；禁止把前一案例的上下文带入下一案例。
2. 先判输出模式：`PROMPT` 必须一次性交付完整提示词；`REPORT` 必须只做证据化诊断；`BLOCK` 必须定位冲突且不偷偷替用户改拍法。
3. 逐项核对 `must_preserve`、`must_not_invent`、`critical_failures` 和 `allowed_variants`。
4. 再按七个维度评分。`allowed_variants` 内的合理差异不得扣分，也不得因为没有逐字匹配参考表达而扣分。
5. mutations 只在一份原本通过的回复上引入所述一个缺陷，用于确认评审能稳定识别问题；不得同时加入第二个缺陷。

## 2. 七维评分

每项取 0–3 分：

- `3`：完整、明确，没有需要修复的问题。
- `2`：核心正确，只有不影响执行或连续性的轻微表达问题。
- `1`：部分成立，但存在会明显降低成片质量或理解稳定性的缺陷。
- `0`：缺失、与来源相反或不可执行。

### A. source_fidelity — 来源忠实与证据边界

按控制维度保留用户、批准分镜、真实视频和授权素材的锁定事实；真实视频尾段控制延长开始前已经存在的声画状态，批准分镜控制新增内容。未提供且存在多种选择的摄影、表演、声音或剧情信息不自行补写。

### B. spatial_visibility — 空间、视点与可见性

世界位置、屏幕位置、人物朝向、完整/局部入画、画外存在、前后景、遮挡和视点承载者相互成立。合法背面反打不得误判；严格 POV 的物理矛盾必须阻断。

### C. continuity_extension — 状态连续与延长接缝

人物、道具、伤势、接触、动作阶段和持续声音可跨镜追踪。延长任务使用一句前情与最小接缝；前情只概括已完成事件，当前状态只放在接缝。新增镜头1从首个新变化开始，允许执行首个动作所需的最小依赖簇，不复述整套尾帧，也不重演已完成动作。

### D. shot_executability — 镜头完整与可拍性

`compile/revise` 每镜用自然完整中文交代镜头看见什么、主体在哪里、动作怎样发生，并包含景别、观察关系、主要构图、可见受光和焦点对象。简单焦点只保证主要动作可读，不能借此虚构景深或拉焦；前后景、遮挡、虚焦等只在影响画面可读性、来源锁定或防歧义时保留。`diagnose: observed_failure` 要求首个偏离点、证据、根因与影响范围足以指导下一步；`diagnose: prompt_preflight` 要求首个文本缺陷、来源证据、可预见风险与影响范围，不得冒充成片诊断。所有输出都不能靠虚构信息制造“完整”。

### E. asset_dialogue_sound — 素材、对白与声音绑定

角色、场景、道具、视频和音频各司其职；`声音：`只绑定已提供的音频或音色素材，普通环境音、动作声和对白留在所属镜头。对白逐字、说话人、次数和可见口型要求正确；声音素材不擅自扩展成新台词、音乐或 Foley。

### F. delivery_completeness — 交付完整性

`compile/revise` 的镜数、顺序、时间轴和命名符合任务路由，所有批准镜头在一个代码块中一次性交付；延长使用 `新增镜头N`，普通生成不混入延长专属栏目。纯 `diagnose` 不输出改写代码块，只按诊断依据完整报告实际故障或文本预检风险。可选栏目无内容时直接省略。

### G. economy_naturalness — 简洁、自然与信息密度

没有“前景无主体、无遮挡、无明显虚焦、本镜无对白”等空值填充，也不逐镜机械重复“观看落点集中在”等闭包提示语、稳定全局事实、接缝或终态。删减不能损害镜头观察关系、动作与必要连续性。

## 3. 单案例通过门槛

一个 case 只有同时满足以下条件才通过：

- 输出模式与 `expected_outcome` 一致；
- 所有 `must_preserve` 成立；
- 没有命中 `must_not_invent` 或 `critical_failures`；
- 七个维度均不低于 2 分；
- 总分不低于 18/21。

`critical_failures` 是硬门禁，不能用其他维度高分抵消。阻断案例不要求代码块；它的完整交付是指一次性说清冲突、影响和可选方向。纯诊断案例同样不要求代码块，但必须一次性给出证据、首个偏离点、原因和可选下一步。

## 4. 候选版相对旧版的无回退门槛

对同一 case 进行盲评时，候选版必须：

- 自身先通过单案例门槛；
- 七个维度中没有一项低于旧版；
- 不能以删除必要镜头信息换取 `economy_naturalness` 提升；
- 全部 case 总分之和不低于旧版，且至少在一个已知问题维度上更好。

若旧版本身命中硬门禁，候选版只需消除该失败并满足本规程，不要求保留旧版错误行为。

## 5. Mutation 判定

每个 mutation 从对应 case 的一份通过回复出发，只注入 `single_defect`。评审应指出：

1. 缺陷发生在哪一镜或哪一栏目；
2. 它违反哪个 oracle 条目或评分维度；
3. 严重级别是否与 manifest 一致；
4. 最小修复应删除、恢复或改写什么，但不顺带重写其他内容。

`expected_dimensions` 是必须被降分的最小维度集合，评审可在证据充分时补充其他直接受影响维度；`oracle_hooks` 是至少必须引用的 oracle 字段。两者都不是穷举所有连带影响。

全部 mutation 都必须被识别。`critical` 漏判一次即阻止发布；`major` 允许评审措辞不同，但不得误判为无问题。

## 6. 合法变体控制

`validity_controls` 不是缺陷注入。评审必须放行其中的合法变体，并确认受保护维度不降分；若把允许的反打重投影、最小接缝锚点或自然句式变化误判为错误，说明门禁特异性不足，同样不能发布。

## 7. 评审记录模板

```text
case_id:
outcome: PASS | FAIL | BLOCKED_CORRECTLY | DIAGNOSED_CORRECTLY
scores: A_/3 B_/3 C_/3 D_/3 E_/3 F_/3 G_/3
must_preserve_missing: []
invented_or_critical: []
allowed_variant_used: []
evidence: 用最短引用定位候选回复中的依据
decision: 一句话结论
```

发布报告必须把确定性格式测试、这套文本语义评测和真实模型成片测试分开列示。通过本套件只能标记为 `text-validated`；在 Seedance/Wan/Hailuo 的选定平台完成实跑前，不得标记为 `video-validated`。
