# 失败诊断与修订

只有用户要求生成前提示词预检、提供失败成片要求诊断，或修改既有完整提示词时读取本文件。先确定诊断依据，再读取对应的最新完整序列、来源、有效素材和可用源视频。

## 两种诊断依据

- `prompt_preflight`：只有完整提示词和来源依据时，定位文本内可确认的来源越界、空间冲突、摄影闭包缺失、连续性断点或机械冗余，并说明可预见风险；不得声称模型已经发生某种偏离，也不得把风险写成实际成片根因。
- `observed_failure`：有失败成片或可验证结果时，从首个实际偏离点开始，以画面证据判断原因；不能仅凭旧提示词推断失败画面。

## 定位原因

从第一个偏离批准分镜或连续状态的镜头开始，区分四类原因：

- 提示词冲突或歧义：机位、可见性、动作、素材职责或继承关系无法同时成立；
- 证据不足：关键站位、尾段状态、身份或道具关系没有可读依据；
- 平台能力或输入模式不支持：按 [platform-evidence.md](platform-evidence.md) 核验；
- 随机生成偏差：提示词与证据闭合，但单次结果偏离。

再把故障归入身份/服装、场景外观、世界空间、画面投影、动作阶段、道具与接触、光线、焦点、对白/口型、声音或时长。不要用增加形容词掩盖几何或证据问题。

## 最小释放，完整交付

纯 `diagnose` 只报告当前证据、首个可确认问题、原因类别、影响范围和可选下一步；`observed_failure` 报告首个实际偏离，`prompt_preflight` 报告首个文本缺陷或风险。两者都不输出改写后的代码块；用户同时要求修复时才进入 `revise`。

`revise` 内部只释放造成故障的字段及其下游依赖，沿动作、道具、站位或声音链修复到下一个稳定边界；其余 `locked`、`observed` 和未受影响的继承事实保持不变。这里的“最小”指修改范围，不是缩短最终提示词。

修订后重新运行证据、摄影闭包、素材职责、空间投影和时间轴自审，并一次性交付当前全部镜头的完整提示词。不得只返回一条替换句、一个镜头或让用户自行拼接。

## 常见诊断方向

| 症状 | 优先检查 |
|---|---|
| 多人都转成正面或站位穿帮 | 是否混用了 POV、越肩和观察机位；是否把 `world_roster` 全写成入画 |
| 人物串脸、串衣或音色错配 | 素材是否绑定多次、职责或有效版本是否冲突 |
| 场景外观漂移 | 场景素材是否缺失或被角色/站位图越权控制 |
| 接缝跳变或动作重演 | 是否读取真实尾段、接缝是否与新增镜头1整段重复 |
| 道具瞬移、换手或伤势复原 | 持有人、左右手、接触点和动作阶段是否连续 |
| 光线随反打翻转 | 是否把世界光源误当成屏幕方向，或未重算本镜受光面 |
| 镜头机械冗余 | 是否把内部空值写成“无运镜、无遮挡、本镜无对白”等句子 |
| 镜头过度省略 | 是否缺少摄影闭包中的机位、构图、受光或焦点 |

若修复需要新增剧情、改镜头功能或重排 cut，交回导演分镜；若关键证据仍缺失，明确索取所需素材；若只剩随机偏差，可建议重试或做对照生成，但要标明这是项目建议并由用户决定。
